# `lib/core/api`

The backend boundary. Widgets and providers never import `package:http` — they call `ApiClient`.

## Layout

```
lib/core/api/
  api_client.dart       the one HTTP client (adds the Firebase ID token)
  api_exception.dart    typed errors (unauthenticated / network / response)
  README.md             this file
lib/src/rust/           GENERATED by flutter_rust_bridge — never edit by hand
rust/shared/            models + validation (used by app and Worker)
rust/core/src/api/      app-side Rust exposed to Dart
rust/api/               the Worker: routes, auth, D1 queries, migrations
```

## How one feature flows

```
Widget → Riverpod notifier
       → Rust `core` (build_*_payload: validate with `shared`, encode JSON)
       → ApiClient.postJson (adds Authorization: Bearer <Firebase ID token>)
       → Worker route: authenticate → parse → validate again → D1
```

The reference slice is feedback: `rust/shared/src/lib.rs` (`NewFeedback`), `rust/core/src/api/feedback.rs`, `rust/api/src/lib.rs` (`create_feedback`), `rust/api/migrations/0001_feedback.sql`, `lib/features/feedback/feedback_provider.dart`. Copy its shape.

## The contract

1. **`package:http` may only be imported inside this folder.**
2. **There is no client-to-database path.** No Firestore, no security rules. If a route does not call `auth::uid_from_request`, it is public.
3. **The uid comes from the token, never from a request body.** `shared` models reject unknown fields, so a smuggled `uid` fails to parse.
4. **Validation lives in `rust/shared` only.** The app calls it through `core` for instant feedback; the Worker calls it again as the real gate. Do not re-implement a rule in Dart.
5. **Timestamps are integers** (seconds since epoch, UTC), set by D1 column defaults. No client clocks in stored data.
6. **No realtime listeners.** Screens fetch on open and on pull-to-refresh. Realtime needs Durable Objects — POST-MVP unless a pillar requires it.

## Adding a table + endpoint

Use `/d1 <table> <field:type> ...` — it scaffolds the migration, the `shared` model + validation + tests, the Worker route, and the `core` payload builder. Then:

```bash
cd rust && cargo test                                   # shared rules
flutter_rust_bridge_codegen generate                    # refresh lib/src/rust
cd rust/api && npx wrangler d1 migrations apply DB --local
```

## Error handling

`ApiClient` throws a subtype of `ApiException`; it never returns `null` for failure. Map them in UI:

| Exception | UI |
|---|---|
| `ApiUnauthenticatedException` | route to sign-in |
| `ApiNetworkException` | offline state + retry |
| `ApiResponseException` 422 | show `body` (user-facing validation message) |
| `ApiResponseException` other | generic error state; report to Sentry |
